# Opinionated-bundle research: core / default / extension lines

## 1. Omakub (DHH) — retired Aug 2026, but the clearest "default-with-optional" case study

**Core.** A bash installer that turns "a fresh Ubuntu installation into a fully-configured, beautiful, and modern web development system by running a single command" [src](https://github.com/basecamp/omakub). Hard gate: `install/check-version.sh` aborts unless "Ubuntu 24.04 or higher" and x86 [src](https://raw.githubusercontent.com/basecamp/omakub/master/install/check-version.sh); the 24.04+ requirement was enforced in v1.1.2 (Jul 2024) [src](https://github.com/basecamp/omakub/releases?page=2). It was "a layer of opinion on top of Ubuntu and GNOME" [src](https://omarchy.org/omakub). Repo layout: `applications/ bin/ configs/ defaults/ install/ migrations/ themes/ uninstall/` [src](https://github.com/basecamp/omakub); `install/` splits into `terminal/` (btop, fastfetch, github-cli, lazydocker, lazygit, neovim, zellij, docker, mise, set-git, plus `optional/` and `required/`) [src](https://github.com/basecamp/omakub/tree/master/install/terminal) and `desktop/` (alacritty, chrome, flameshot, libreoffice, localsend, obsidian, pinta, signal, typora, vlc, vscode, xournalpp, ulauncher, and `set-gnome-*` scripts for theme/hotkeys/dock/extensions) [src](https://github.com/basecamp/omakub/tree/master/install/desktop). Status: archived Aug 30, 2026; 8.1k stars, 801 forks [src](https://github.com/basecamp/omakub). Final release v1.5.0, Nov 9, 2025 [src](https://github.com/basecamp/omakub/releases).

**Default experience.** First run asks three gum prompts with pre-selected answers: optional apps (1password, Spotify, Zoom, Dropbox; defaults 1password/Spotify/Zoom), languages (defaults Ruby on Rails, Node.js), Docker databases (defaults MySQL, Redis) [src](https://raw.githubusercontent.com/basecamp/omakub/master/install/first-run-choices.sh). Everything else in `install/terminal` and `install/desktop` is unconditional.

**Extension unit and interface.** The unit is a shell script per app: `install/desktop/optional/app-<name>.sh` (22 files: 1password, brave, cursor, discord, doom-emacs, gimp, minecraft, obs-studio, retroarch, steam, virtualbox, windsurf, zed, zoom, …) [src](https://github.com/basecamp/omakub/tree/master/install/desktop/optional) with a matching `uninstall/app-<name>.sh` (48 scripts) [src](https://github.com/basecamp/omakub/tree/master/uninstall). The `omakub` TUI is `gum choose` over Theme / Font / Update / Install / Uninstall / Manual / Quit [src](https://raw.githubusercontent.com/basecamp/omakub/master/bin/omakub-sub/menu.sh); Install sub-menu = Development (editor/language/database), Optional apps, Web apps, All, and it resolves a choice to `install/desktop/optional/app-$INSTALLER.sh` by lowercasing the first word [src](https://raw.githubusercontent.com/basecamp/omakub/master/bin/omakub-sub/install.sh). Themes are directories (10: catppuccin, everforest, gruvbox, kanagawa, matte-black, nord, osaka-jade, ristretto, rose-pine, tokyo-night; my count of [src](https://github.com/basecamp/omakub/tree/master/themes)). Project evolution ships as 16 timestamped `migrations/<unix-ts>.sh` (my count of [src](https://github.com/basecamp/omakub/tree/master/migrations)), run by `bin/omakub-sub/migrate.sh` [src](https://github.com/basecamp/omakub/tree/master/bin/omakub-sub).

**Discovery and distribution.** Everything lives in-repo; there is no registry. `EXTENSIONS.md` lists exactly one community extension (a dark/light theme switcher) [src](https://github.com/basecamp/omakub/blob/master/EXTENSIONS.md). Variation happened by forking: omakub-fedora, sunhat (Fedora), omakos and omacub (macOS), omakub-arch, and Omabuntu ("A fork of Omakub, more flexible and refined", Ubuntu 24.04, `wget -qO- https://omabuntu.omakasui.org/install | bash`) [src](https://github.com/topics/omakub) [src](https://omabuntu.omakasui.org/).

**Overriding defaults / "I want to change X".** Officially: use the TUI to uninstall/install; otherwise fork. README: "an opinionated take on what Linux can be at its best" while "the open source community offers alternative customization, add-ons, extras" [src](https://github.com/basecamp/omakub). DHH's launch post frames it for developers coming from Windows/macOS trading "ultimate bespoke customization" for curation, explicitly not for NixOS/Arch people [src](https://world.hey.com/dhh/introducing-omakub-354db366). A proposal for an override/`.ignore` mechanism (issue #154) was closed with no recorded maintainer reply [src](https://github.com/basecamp/omakub/issues/154). DHH's retirement note: "good ideas don't retire, they get forked!" [src](https://omarchy.org/omakub). The literal "it's my setup; fork it" phrasing: unverified.

**Lessons.** Fresh-install-only was the recurring wound: DHH himself opened "Warn on setup that Omakub is for a FRESH 24.04 setup" ("I've seen at least one person mention that Omakub screwed something up on their main machine … this is for a fresh system, you should have a backup") [src](https://github.com/basecamp/omakub/issues/63). HN: "super intrusive and reconfigures your entire system" and "impossible to remove" (theamk), "Opinionated == installs a lot of shit you'll probably never use" (oweiler) [src](https://news.ycombinator.com/item?id=40591112); "It crashed during the run and left the system half-configured" (quasarj), scripts are "terrible for maintenance … you can't undo" (tasuki) [src](https://news.ycombinator.com/item?id=40630174); Lobsters: "I have decided that you should use 1Password and Spotify" (strugee), Universal Blue would abstract more (cflewis), but also "a good starter to fork and make your own" (Sirikon) [src](https://lobste.rs/s/skak3k/omakub_opinionated_ubuntu_setup). Defence: it "solves the discovery problem" for newcomers (EricRiese) [src](https://news.ycombinator.com/item?id=40591112). Version trajectory: v1.1.0 (Jul 2024) added the standalone TUI and first optional apps; later releases kept moving things to optional (Minecraft/GIMP/Tailscale in 1.3.0, Discord in 1.4.1) and adding uninstallers (VirtualBox 1.2.0, dev-language 1.1.8, VSCode 1.4.0) [src](https://github.com/basecamp/omakub/releases) [src](https://github.com/basecamp/omakub/releases?page=2). Ultimately the layer-on-top model lost: "those come with strong opinions of their own", so DHH moved to owning the whole stack (Omarchy) [src](https://omarchy.org/omakub).

## 2. Omarchy (DHH) — opinionated distro that still lets you change things

**Core.** "An omakase Linux distribution based on Arch, the tiling window manager Hyprland, and the desktop construction-kit Quickshell" [src](https://omarchy.org/manual/). Fixed: Hyprland; the `omarchy` CLI (`omarchy update`, `omarchy theme set`, `omarchy menu`, `omarchy debug`, …; "every command takes --help") [src](https://omarchy.org/manual/omarchy-cli/); `/usr/bin/omarchy-*` binaries and `/usr/share/omarchy/` (themes, shell, migrations, install scripts) owned by packages [src](https://raw.githubusercontent.com/omacom/omarchy/master/docs/file-layout.md); 122 timestamped `migrations/*.sh` (my count of [src](https://github.com/omacom/omarchy/tree/master/migrations)); 22 theme dirs (my count of [src](https://github.com/omacom/omarchy/tree/master/themes)); mandatory LUKS, ufw default-deny inbound (except LocalSend 53317), sshd off until enabled [src](https://omarchy.org/manual/security/). Numbers: 42k stars [src](https://github.com/omacom/omarchy); "1,153,463 ISO downloads in year one", "$18.7 million pledged to Omacom Foundation" [src](https://omarchy.org/).

**Default experience.** "Write the ISO to a USB stick and answer five questions"; install "in as little as 35 seconds" [src](https://omarchy.org/). 4.0 made the default coding agent a first-run setting (Claude Code, Codex, OpenCode, Pi, Gemini, Grok, Copilot) and moved Signal/Spotify/1Password to on-demand, removed Figma/GitHub web apps [src](https://github.com/omacom/omarchy/releases/tag/v4.0.0). Unwanted preinstalls are removed via "Remove > Preinstalls" [src](https://omarchy.org/manual/faq/).

**Extension unit and interface.** (a) Plugins (since 4.0 "Quattro"): a git repo with `manifest.json` at root (`schemaVersion`, `id`, `name`, `version`, `kinds`, `entryPoints`), kinds `bar-widget | bar | panel | overlay | menu | service`; cloned to `~/.config/omarchy/plugins/<id>/`; `omarchy plugin add <url> | update | remove | enable | disable`; third-party code gets "capability-scoped facades"; state in `shell.json`, look in `shell.toml` [src](https://raw.githubusercontent.com/omacom/omarchy/master/docs/omarchy-shell.md). (b) Themes in `~/.config/omarchy/themes` [src](https://learn.omacom.io/2/the-omarchy-manual). (c) Project migrations: run per user after pacman, tracked as markers in `~/.local/state/omarchy/migrations/<filename>`, `omarchy-migrate --pending` [src](https://raw.githubusercontent.com/omacom/omarchy/master/docs/update-process.md).

**Discovery and distribution.** Marketplace plugins.omarchy.org backed by `omacom/omarchy-plugin-marketplace`: submit via issue form; "an explicit `approved-and-verified` maintainer decision before publication"; plugins "execute as unsandboxed code"; IDs must be namespaced outside `omarchy.*`; must not "overwrite user configuration without explicit consent" [src](https://github.com/omacom/omarchy-plugin-marketplace) [src](https://github.com/omacom/omarchy-plugin-marketplace/blob/main/SUBMISSION.md). The fetched page showed "0 community plugins" (likely JS-rendered; count unverified) [src](https://plugins.omarchy.org/).

**Overriding defaults.** The contract is ownership by directory: "The files that live in `~/.local/share/omarchy` belong to Omarchy itself … you should be overwriting the value in `~/.config` instead" [src](https://learn.omacom.io/2/the-omarchy-manual); in 4.x the system copy is `/usr/share/omarchy` and `~/.config/hypr/hyprland.lua` "Loads the Omarchy defaults plus your override files below" (`bindings.lua`, `monitors.lua`, `input.lua`, `looknfeel.lua`, `autostart.lua`) [src](https://omarchy.org/manual/dotfiles/). Common tweaks are documented as uncommenting lines in those files; updates may refresh configs with `.bak` backups, and `omarchy-reinstall` resets everything [src](https://omarchy.org/manual/common-tweaks/). Updates go through `omarchy update` (snapshot, packages, migrations); "all your user config changes to the Omarchy defaults will be overwritten" only on `omarchy reinstall`; channels stable/edge/rc/dev; rollback via snapshot [src](https://omarchy.org/manual/updates/); running `pacman -Syu` directly is warned against [src](https://learn.omacom.io/2/the-omarchy-manual/68/updates), and 4.0 added an ALPM guard (bypass `OMARCHY_ALLOW_DIRECT_PACMAN=1`) [src](https://github.com/omacom/omarchy/releases/tag/v4.0.0). Manual stance: "this is your computer. You're free to change everything" [src](https://omarchy.org/), and "It's not trying to be as familiar as possible. It's trying to be beautiful and better" [src](https://omarchy.org/manual/).

**Lessons.** Versions: 1.0 Jun 26, 2025, a post-install script, "It's not for everyone", "sister project to Omakub" [src](https://world.hey.com/dhh/omarchy-is-out-4666dd31); 2.0 Aug 26, 2025: ISO, AUR-free, own package repo [src](https://world.hey.com/dhh/omarchy-2-0-16fefc15); 3.0 Sep 17, 2025: offline 7GB ISO, pre-M MacBooks [src](https://github.com/basecamp/omarchy/releases/tag/v3.0.0); 4.0.0 Aug 14, 2026: Quickshell shell replacing Waybar/Walker/Mako/hyprlock/etc., plugin architecture, real Arch packages, pkexec/polkit, factory reset, "Unsecured sudoers grants removed" [src](https://github.com/omacom/omarchy/releases/tag/v4.0.0); 4.0.4 Sep 15, 2026 [src](https://github.com/basecamp/omarchy/releases). Security criticism: docker-group root escalation in every version before 4.0.1, fixed Aug 24, 2026; author: "I do not trust the decision making process as it stands" [src](https://0xcc.io/posts/omarchy-root-creds/); `curl | sh`, mise bypassing pacman, firewall not autostarting in 3.0.2, migrations without `set -eEo pipefail`, and "lacking truly opinionated defaults" for tmux/swap/power [src](https://xn--gckvb8fzb.com/a-word-on-omarchy/); 451 shellcheck errors across 473 files vs defenders' "polished desktop experience without hours of configuration" [src](https://biggo.com/news/202510230813_Omarchy-Linux-Community-Debate). Omarchy documents its own footgun honestly: passwordless-sudo mode "anything running as your user can do anything as root without being asked" [src](https://omarchy.org/manual/security/).

## 3. oh-my-zsh — the in-repo plugin monorepo

**Core.** "A delightful community-driven (with 2,500+ contributors) framework for managing your zsh configuration", ~189.8k stars, installed by `sh -c "$(curl -fsSL …/tools/install.sh)"` [src](https://github.com/ohmyzsh/ohmyzsh).

**Default experience.** The template `.zshrc` sets `ZSH_THEME="robbyrussell"` and `plugins=(git)`; all update `zstyle` lines are commented out [src](https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/templates/zshrc.zsh-template); default behaviour is a prompt to update every 13 days, `omz update` is a git pull, modes `auto|reminder|disabled` [src](https://github.com/ohmyzsh/ohmyzsh/wiki/Settings).

**Extension unit and interface.** `plugins/<name>/<name>.plugin.zsh` (each with its own README) enabled by name in the `plugins=()` array [src](https://github.com/ohmyzsh/ohmyzsh/wiki/Plugins); `themes/<name>.zsh-theme`; `$ZSH_CUSTOM` (default `$ZSH/custom`): "Whatever you place inside of it will take precedence over the built-in configuration" — `custom/plugins/<name>/<name>.plugin.zsh`, `custom/themes/<name>.zsh-theme`, `custom/*.zsh`, and `custom/lib/<name>.zsh` to fully override a lib file; the custom dir is git-ignored so updates never touch it [src](https://github.com/ohmyzsh/ohmyzsh/wiki/Customization). No lifecycle hooks: a plugin is just sourced.

**Discovery and distribution.** In-repo monorepo: 367 plugin directories and 143 `.zsh-theme` files (my count of [src](https://github.com/ohmyzsh/ohmyzsh/tree/master/plugins) and [src](https://github.com/ohmyzsh/ohmyzsh/tree/master/themes)); README says "300+ optional plugins" and "140+ themes" [src](https://github.com/ohmyzsh/ohmyzsh). The PR gate is deliberately tight: "Please do not send themes for now"; "For any extensive change, such as a new plugin, you will have to find testers to +1 your PR"; "maintained by a small team of volunteers" with "hundreds of pending PRs" [src](https://github.com/ohmyzsh/ohmyzsh/blob/master/CONTRIBUTING.md). Popular externals (zsh-users' autosuggestions/syntax-highlighting) live outside the repo and drop into `custom/plugins` [src](https://en.wikipedia.org/wiki/Z_shell).

**Overriding defaults.** Same mechanism as extending: shadow by name in `custom/`, or point `ZSH_CUSTOM` at your own repo [src](https://github.com/ohmyzsh/ohmyzsh/wiki/Customization).

**Lessons.** The "too much / slow" complaint is perennial in the tracker: "oh-my-zsh very slow" [src](https://github.com/ohmyzsh/ohmyzsh/issues/5327), "4-5s" [src](https://github.com/ohmyzsh/ohmyzsh/issues/8536), 30 s [src](https://github.com/ohmyzsh/ohmyzsh/discussions/11651), the update check itself hitting the network on startup [src](https://github.com/ohmyzsh/ohmyzsh/issues/11617). A widely cited benchmark concludes "Time-consuming plugins are the main causes of a slow startup", not the framework (~60 ms clean) [src](https://gist.github.com/laggardkernel/4a4c4986ccdcaf47b91e8227f9868ded). Reactions: Prezto (started from Sorin Ionescu's OMZ fork, "The next generation of oh-my-zsh?" [src](https://github.com/sorin-ionescu/prezto/issues/223) [src](https://github.com/sorin-ionescu/oh-my-zsh)) with modules "disabled by default" [src](https://github.com/sorin-ionescu/prezto); Zim "focuses on execution speed" [src](https://en.wikipedia.org/wiki/Z_shell); zinit turbo mode, antidote, zplug [src](https://gist.github.com/laggardkernel/4a4c4986ccdcaf47b91e8227f9868ded). The maintainer's defence is explicitly the beginner: "a lot of people will argue that Oh My Zsh is just completely bloated … I think it's a couple of megabytes" [src](https://changelog.com/podcast/465); "a cozy way to get introduced to it"; he refused complexity because "it's going to make it complicated for people that don't have a lot of experience with the command line" [src](https://www.opensourcestories.org/stories/2023/robby-russell-ohmyzsh/). Takeaway: tiny default (`git` only), huge in-tree optional catalogue, strict gate on additions.

## 4. k3s vs Kubernetes — batteries included, every battery removable

**Core.** "A fully conformant production-ready Kubernetes distribution" in a single binary; removes "In-tree storage drivers" and "In-tree cloud provider" (CSI/CCM out-of-tree instead) [src](https://github.com/k3s-io/k3s). The earlier claim that "Legacy, alpha, non-default features are removed" was retracted in 2019 ("we added those things back in recently") [src](https://github.com/k3s-io/k3s/issues/1017). Bundled: containerd/runc, Flannel, CoreDNS, Traefik, ServiceLB (klipper-lb), kube-router policy, local-path-provisioner, metrics-server, helm-controller, kine, Spegel [src](https://docs.k3s.io/) [src](https://github.com/k3s-io/k3s). Datastore: "SQLite is the default datastore"; embedded etcd auto-selected on init/join; external Postgres/MySQL/etcd via `--datastore-endpoint` [src](https://docs.k3s.io/datastore). CNCF Sandbox since Aug 19, 2020 [src](https://www.cncf.io/projects/k3s/); ~34k stars [src](https://github.com/k3s-io/k3s).

**Default experience.** `curl -sfL https://get.k3s.io | sh -` installs a systemd service plus kubectl/crictl/ctr and a kubeconfig at `/etc/rancher/k3s/k3s.yaml`; agents join with `K3S_URL`/`K3S_TOKEN` [src](https://docs.k3s.io/quick-start). Traefik, ServiceLB and CoreDNS deploy automatically on start [src](https://docs.k3s.io/networking/networking-services).

**Extension unit and interface.** Drop any manifest into `/var/lib/rancher/k3s/server/manifests`; it is applied at startup and on file change and tracked as an `AddOn` CR in kube-system (filenames must be DNS-safe) [src](https://docs.k3s.io/installation/packaged-components). `HelmChart` CRD (`chart`, `repo`, `version`, `targetNamespace`, `valuesContent`, `set`) and `HelmChartConfig` (same name/namespace as the packaged chart, e.g. `traefik-config.yaml` with `valuesContent`) enable "cluster bootstrap through a single file on disk" [src](https://raw.githubusercontent.com/k3s-io/docs/main/docs/add-ons/helm.md). Packaged component manifests are regenerated every startup, so customisation must go through HelmChartConfig, not edits [src](https://docs.k3s.io/networking/networking-services).

**Discovery and distribution.** No registry: Helm repos/OCI charts and files on disk.

**Overriding defaults.** `--disable=traefik,servicelb,coredns,local-storage,metrics-server` (also uninstalls), or a `<name>.yaml.skip` file [src](https://docs.k3s.io/installation/packaged-components); `--flannel-backend=none` plus `--disable-network-policy` for your own CNI [src](https://docs.k3s.io/networking/basic-network-options).

**Lessons.** The bundled-Traefik debate (#6215, Oct 2022): proposer noted "Traefik phones home by default" and version lag; maintainer brandond: "K3s is a CNCF project, and we aim to keep it as open and independent as possible", K3s intentionally includes "components necessary for a fully functional cluster", and `--disable traefik` removes an installed one; outcome: kept [src](https://github.com/k3s-io/k3s/discussions/6215). Neighbours draw the line differently: k0s = "The Zero Friction Kubernetes", "100% upstream", single binary, no opinionated add-ons [src](https://docs.k0sproject.io/stable/); MicroK8s = a core with `microk8s enable dns|ingress|hostpath-storage|metallb` plus a community addon repo (`microk8s enable community`: Cilium, Istio, Traefik) [src](https://canonical.com/microk8s/docs/addons); k3d = "a lightweight wrapper to run k3s … in docker", `k3d cluster create mycluster` [src](https://k3d.io/stable/). The "not real Kubernetes" jab is answered by conformance ("fully conformant") [src](https://github.com/k3s-io/k3s).

## 5. Talos Linux — the "no shell, change it via the API" extreme

**Core.** "Talos is managed by a single, declarative gRPC API"; immutable SquashFS; "no shells, SSH, GNU utilities, and busybox"; "There are no passwords in Talos" [src](https://docs.siderolabs.com/talos/v1.14/overview/what-is-talos.md) [src](https://docs.siderolabs.com/talos/v1.14/learn-more/philosophy). Marketing: "No SSH, no shell, no package manager", "<50 OS binaries", "110k+ nodes" [src](https://www.siderolabs.com/talos-linux/); 11.2k stars [src](https://github.com/siderolabs/talos).

**Default experience.** Boot an image, `talosctl gen config`, apply; a single YAML "defines all Talos and Kubernetes settings—no scripts or procedural steps" [src](https://docs.siderolabs.com/talos/v1.14/learn-more/philosophy).

**Extension unit and interface.** System extensions are OCI images with `manifest.yaml` + `rootfs`, signed with cosign, ~90+ across tiers core/extra/contrib (runtimes, drivers, firmware, ZFS/NFS/iSCSI, Tailscale/WireGuard, guest agents, NVIDIA) [src](https://github.com/siderolabs/extensions). They are "only activated during the installation or upgrade", i.e. baked into the image, never installed at runtime; `talosctl get extensions` lists them; upgrades mean regenerating the installer [src](https://docs.siderolabs.com/talos/v1.14/build-and-extend-talos/custom-images-and-development/system-extensions.md).

**Discovery and distribution.** Image Factory: POST a schematic (`customization.systemExtensions.officialExtensions`, `extraKernelArgs`, `overlay`, `meta`) to `factory.talos.dev/schematics`, get a content-addressed ID, download ISO/PXE/installer/disk images; `imager` for private extensions [src](https://docs.siderolabs.com/talos/v1.14/platform-specific-installations/boot-assets.md).

**Overriding defaults.** Config patches: "Strategic merge patches look like incomplete machine configuration files", JSON patch auto-detected; `--config-patch` at gen time, `talosctl machineconfig patch`, `talosctl patch mc --nodes …` [src](https://docs.siderolabs.com/talos/v1.14/configure-your-talos-cluster/system-configuration/patching.md).

**Lessons.** Sidero's own tongue-in-cheek admission: "Talos doesn't have SSH … it doesn't even have the sshd binary", "Maybe you have too much muscle memory for netstat", with `talosctl services/logs/dmesg/dashboard/netstat/pcap` as substitutes [src](https://www.siderolabs.com/blog/how-to-ssh-into-talos-linux). The pressure won partially: v1.13.0 (Apr 2026) shipped `talosctl debug`, a privileged ephemeral host-namespace container, two years after the request [src](https://bex.co/blog/2026/09/09/talos-talosctl-debug-ephemeral-host-container). "The learning curve is real" for SSH/Ansible teams [src](https://oneuptime.com/blog/post/2026-03-03-decide-when-to-use-talos-linux/view).

## 6. Fedora Silverblue / Universal Blue — immutable base + layers + opinionated images

**Core.** Silverblue is "an atomic GNOME-based desktop"; rpm-ostree is "a hybrid image/package system"; "The whole system is updated in one go"; "A previous version of your system is always kept around"; apps via Flatpak, dev via Toolbx [src](https://fedoraproject.org/atomic-desktops/silverblue/). Direction: "The next major evolution for the Atomic Desktops will be to transition to Bootable Containers" [src](https://planet.kde.org/siosms-blog-2025-10-28-whats-new-for-fedora-atomic-desktops-in-fedora-43/); roadmap done items include publishing bootable container images and composefs, open items include layering and default delivery; "rpm-ostree likely to stay in the image for a while" [src](https://gitlab.com/fedora/ostree/sig/-/issues/26). bootc = "Transactional, in-place operating system updates using OCI/Docker container images" [src](https://github.com/containers/bootc).

**Extension unit.** Package layering: `rpm-ostree install` creates a new deployment; "every rpm-ostree operation is 'offline' … will only take effect when you reboot" (`-A` applies live); "While most software should go into a container, you have full flexibility to use packages where it suits" [src](https://coreos.github.io/rpm-ostree/administrator-handbook/). Universal Blue builds "continuously delivered operating system images using bootc" from a Containerfile + GitHub Actions template (Bluefin, Bazzite, Aurora) [src](https://universal-blue.org/).

**Overriding defaults.** Bluefin: "Adding packages directly onto the host image is discouraged"; Flatpak for GUI, Homebrew for CLI, Distrobox/devcontainers for workloads; `ujust --choose`, `ujust update`, `ujust rebase-helper`, `ujust devmode` [src](https://docs.projectbluefin.io/administration/); bluefin-dx keeps "the operating system and developer environment … explicitly and purposely separated"; "Critics will say we ship too many package managers, we say we don't ship package managers, we ship ecosystems that users want" [src](https://docs.projectbluefin.io/bluefin-dx/).

**Lessons.** Reboot-per-layer friction, Flatpak permission UX, and "there's still a learning curve for doing everything in the immutable way" [src](https://www.mauromorales.com/2025/10/27/fedora-silverblue-first-impressions-from-someone-building-an-immutable-system/); layered packages break major upgrades ("the upgrade will fail citing dependency issues" → `rpm-ostree reset`), yet maintainers say "it's _your_ system, so if you want to install things via rpm-ostree, then do it" [src](https://discussion.fedoraproject.org/t/silverblue-layered-packages/145752).

## 7. Tailscale defaults — and fencing a tagged VM

**Default experience.** `tailscale up` connects and authenticates; on Linux `--accept-routes` defaults off, `--ssh` false, exit-node/shields-up off; `tailscale set` changes single prefs [src](https://tailscale.com/kb/1080/cli). MagicDNS "enabled by default" for tailnets created on/after Oct 20, 2022 [src](https://tailscale.com/kb/1081/magicdns). Default policy "enables communication between all devices within the tailnet" [src](https://tailscale.com/kb/1018/acls), literally `{"acls":[{"action":"accept","src":["*"],"dst":["*:*"]}]}` [src](https://tailscale.com/docs/reference/examples/acls). Key expiry: "new domains are set with an expiry period of 180 days" (1–180) [src](https://tailscale.com/kb/1028/key-expiry). "All connections start as relayed through a DERP server, and Tailscale then tries to upgrade them to a direct connection" [src](https://tailscale.com/kb/1257/connection-types); the coordination server is "a shared drop box for public keys" [src](https://tailscale.com/blog/how-tailscale-works).

**Customisation.** HuJSON policy file with ACLs or grants ("Grants can do everything ACLs can, plus …"; src/dst/ip/app) [src](https://tailscale.com/kb/1324/grants); tags: "Applying a tag to a device removes any user-based authentication", key expiry disabled by default for tagged devices [src](https://tailscale.com/kb/1068/tags); autogroups incl. `autogroup:member`, `autogroup:tagged`, `autogroup:self`, `autogroup:internet` [src](https://tailscale.com/kb/1337/acl-syntax).

**Fencing a VM (your use case).** Rules are directional and deny-by-default: "Tailscale access rules deny access by default" [src](https://tailscale.com/kb/1337/acl-syntax); "Allowing a source to connect to a destination doesn't mean the destination can connect to the source (unless a policy explicitly enables it)" [src](https://tailscale.com/kb/1018/acls). So a `tag:vm` that appears only in `dst` (e.g. `src: ["autogroup:member"], dst: ["tag:vm:*"]`) can be reached but cannot initiate tailnet connections. Caveat: "ACLs do not affect what a device can or cannot access on its local network" [src](https://tailscale.com/kb/1018/acls), so the fence covers the tailnet only, not LAN/internet egress.

**Lessons.** Closed control plane: "Everything in Tailscale is Open Source, except the GUI clients for proprietary OS … and the control server" → Headscale, whose maintainer is employed by Tailscale [src](https://github.com/juanfont/headscale) [src](https://tailscale.com/opensource). ACL learning curve is acknowledged by Tailscale itself ("intimidated by their perceived complexity") [src](https://tailscale.com/blog/getting-started-with-tailscale-acls); a common confusion is "no way to deny in any specific rule, only a default deny policy" [src](https://anuragbhatia.com/post/2024/04/understanding-headscale-tailscale-acl/).

## Cross-cutting patterns (derived from the above)

- Tiny hard core + pre-selected defaults + per-unit remove: Omakub's first-run prompts with defaults, OMZ's `plugins=(git)`, k3s `--disable`. Every long-lived project grew an uninstall path after users demanded it.
- Ownership-by-directory beats "don't touch": Omarchy (`~/.config` yours, `/usr/share/omarchy` theirs, defaults sourced then overridden), OMZ `custom/` precedence, Talos patches, k3s HelmChartConfig. Rerunnable state markers (Omarchy `~/.local/state/omarchy/done`) fix the "half-configured / can't undo" complaint that dogged Omakub.
- Extension unit = a git repo with a manifest, unsandboxed, with a curated listing separate from core (Omarchy plugins, MicroK8s community addons). Themes and app installers stay in-repo; behaviour plugins go external.
- Security defaults draw the loudest criticism (curl|bash, docker group, passwordless sudo), and documenting the trade-off explicitly (Omarchy's security page) is what critics respected.
