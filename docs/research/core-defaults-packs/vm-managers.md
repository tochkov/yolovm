# Core / default / extension lines in Lima, Colima, Multipass, Vagrant

## 1. Lima

**Core.** Lima's one-liner: "Lima launches Linux virtual machines with automatic file sharing and port forwarding (similar to WSL2)"; it was created to "promote containerd including nerdctl to Mac users" ([README](https://raw.githubusercontent.com/lima-vm/lima/master/README.md)). Core = `limactl` + internal drivers (qemu, vz, wsl2 compiled in via build tags) + a gRPC driver interface for external drivers ([drivers](https://lima-vm.io/docs/dev/drivers/)). The "bare" switch is **plain mode**: `plain: true` / `--plain` disables mounts, dynamic port forwarding, built-in containerd and the guest agent, Rosetta, agent forwarding and clock sync, while static port forwards and provision scripts still run; plain `ssh` is "often preferred to keep the guest free of Lima-specific conventions" ([plain](https://lima-vm.io/docs/config/plain/)). v2.0.0 (2025‑11‑06) added the "Experimental plug-in subsystem for VM driver infrastructure", CLI plugins, URL-scheme plugins, an external krunkit driver, MCP integration, and moved the project to CNCF Incubating ([v2.0.0](https://github.com/lima-vm/lima/releases/tag/v2.0.0), [API date](https://api.github.com/repos/lima-vm/lima/releases/tags/v2.0.0)). Latest: v2.2.0 (2026‑07‑25), v2.3.0‑beta.0 (2026‑09‑01) ([atom](https://github.com/lima-vm/lima/releases.atom)).

**Default experience.** "To create an instance 'default' (if not created yet) from the default Ubuntu template, and start it: `$ limactl start`" ([ref](https://lima-vm.io/docs/reference/limactl_start/)). In a TTY it shows `? Creating an instance "default"` with four options: proceed with current configuration, open an editor, choose another template (docker, podman, archlinux, fedora…), exit; "`--tty=false` flag can be used for disabling the interactive user interface" ([usage](https://lima-vm.io/docs/usage/)). That prompt is a recurring automation papercut ([discussion #1420](https://github.com/lima-vm/lima/discussions/1420); a `--yes` alias exists per search results, unverified). `default.yaml`: vmType "vz" on macOS ≥13.5 else "qemu"; cpus `min(4, host)`, memory `min('4GiB', half of host)`, disk 100GiB; `base: [template:_images/ubuntu]` (→ `ubuntu-26.04.yaml` symlink) and `template:_default/mounts` (home read‑only; "/tmp/lima is no longer mounted by default since Lima v2.0"); mountType 9p (QEMU) / virtiofs (vz); `containerd.system: false`, `containerd.user: true` on x86_64/aarch64 Linux guests; no portForwards; `ssh.localPort: 0`; `loadDotSSHPubKeys: false (since Lima v1.0)` ([default.yaml](https://raw.githubusercontent.com/lima-vm/lima/master/templates/default.yaml), [mounts.yaml](https://raw.githubusercontent.com/lima-vm/lima/master/templates/_default/mounts.yaml), [_images/ubuntu.yaml](https://github.com/lima-vm/lima/blob/master/templates/_images/ubuntu.yaml)). v2.0 also forwards UDP by default and stopped hard-coding SSH port 60022 ([v2.0.0](https://github.com/lima-vm/lima/releases/tag/v2.0.0)).

**Extension unit and interface.** (a) Template YAML: `provision:` modes `system`, `user`, `boot`, `dependency`, `data`, `yq`, and `ansible` ("DEPRECATED"); `probes:` "Only `readiness` probes are supported right now" ([default.yaml](https://raw.githubusercontent.com/lima-vm/lima/master/templates/default.yaml)). Composition via `base:` (PR #3072, merged 2025‑03‑04, v1.1.0): scalars copied if absent, lists appended (reversed for `provision`/`probes`), `mounts`/`networks`/`additionalDisks` merged by key; the instance's `lima.yaml` is a flattened composite ([PR #3072](https://github.com/lima-vm/lima/pull/3072)). (b) CLI plugins: executables named `limactl-<command>`, found in limactl's own dir, `$PATH`, then `<PREFIX>/libexec/lima`; listed in `limactl --help` under "Available Plugins (Experimental)" with descriptions read from a `<limactl-desc>` comment; "Lima >= 2.0" ([cli](https://lima-vm.io/docs/config/plugin/cli/)). (c) URL handlers `limactl-url-<scheme>`: Lima "calls the plugin with the part after the colon as its sole argument", stdout must be a URL or path, chains resolve until an `https:` URL/file ([url](https://lima-vm.io/docs/config/plugin/url/)). (d) Drivers `lima-driver-<name>` via `LIMA_DRIVERS_PATH` or `libexec/lima`, gRPC per `driver.proto` ([drivers](https://lima-vm.io/docs/dev/drivers/)). No install/configure/sign-in lifecycle exists; "check" = readiness probes.

**Discovery and distribution.** In-repo `templates/` with `_default/`, `_images/`, `experimental/` plus ~65 YAMLs ([listing](https://api.github.com/repos/lima-vm/lima/contents/templates)); referenced as `template:NAME` (2.x; 1.x used `template://`), or any local file/URL; `--list-templates` ([templates](https://lima-vm.io/docs/templates/), [ref](https://lima-vm.io/docs/reference/limactl_start/)). Templates carry tier marks ⭐/☆ "Regularly tested on the CI" ([templates README](https://raw.githubusercontent.com/lima-vm/lima/master/templates/README.md)). A "Lost+found" section records removals: CentOS 7/8, Nomad ("no longer free software"), experimental network templates merged into default or replaced by CLI flags, Singularity→Apptainer ([templates](https://lima-vm.io/docs/templates/)). URL-handler plugins let an org map `dev:webapp` to a git raw URL ([url](https://lima-vm.io/docs/config/plugin/url/)).

**Overriding defaults.** `~/.lima/_config/default.yaml` is "used by ALL instances under the same $LIMA_HOME"; `override.yaml` "takes precedence even over the settings in an instances lima.yaml file"; experimental `base.yaml` is merged only at creation; lists/maps combine with priority override > lima.yaml > default.yaml ([default.yaml](https://raw.githubusercontent.com/lima-vm/lima/master/templates/default.yaml)). `--set` = "Modify the template inplace, using yq syntax. Can be passed multiple times." plus flag sugar (`--cpus`, `--memory`, `--mount ...:w`, `--mount-writable`, `--containerd`, `--vm-type`, `--plain`) on `start`/`create`/`edit`; `limactl edit INSTANCE|FILE.yaml --start` ([start](https://lima-vm.io/docs/reference/limactl_start/), [edit](https://lima-vm.io/docs/reference/limactl_edit/)).

**Lessons.** Read-only home is the classic "too bare/surprising" complaint; the FAQ states it flatly ([FAQ](https://lima-vm.io/docs/faq/)); RFC #1872 (2023‑10‑01) to flip it for v1.0 was closed not-planned: "I still want to minimize having breaking changes, and the mount can be easily configured to be writable with `limactl start --mount-writable`" ([#1872](https://github.com/lima-vm/lima/issues/1872)). Things that moved into core: v1.0.0 (2024‑11‑06) made VZ default on macOS ≥13.5, merged `experimental/vz` into `default`, removed vmnet/experimental network+mount templates in favour of CLI flags, and promised "The `limactl` CLI is designed to print hints when the user hits those breaking changes" ([v1.0.0](https://github.com/lima-vm/lima/releases/tag/v1.0.0)); v2.0 removed `/tmp/lima` and added the plugin tiers ([v2.0.0](https://github.com/lima-vm/lima/releases/tag/v2.0.0)). Why others layered on it: Colima calls itself "a higher level usage of Lima" ([Colima FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)); its maintainer: "Colima is specifically focused on providing container runtimes while Lima is more focused on providing virtual machines" ([#1349](https://github.com/abiosoft/colima/discussions/1349)); Finch is "a minimal native client along with an opinionated distribution of other open source components" (nerdctl, containerd, BuildKit, Lima) ([Finch](https://raw.githubusercontent.com/runfinch/finch/main/README.md)); Rancher Desktop is listed among projects using Lima and its FAQ refers to "the (lima) VM" ([README](https://raw.githubusercontent.com/lima-vm/lima/master/README.md), [RD FAQ](https://docs.rancherdesktop.io/faq/)). Versus Multipass, the maintainer cites localhost port forwarding, multi-distro support and rootless install ([#579](https://github.com/lima-vm/lima/discussions/579)).

## 2. Colima

**Core.** "Containers on Lima"; Homebrew formula `depends_on "lima"` ([formula](https://raw.githubusercontent.com/Homebrew/homebrew-core/master/Formula/c/colima.rb)). Runtimes: docker (default), containerd, incus, none; `--kubernetes` (k3s); GPU via krunkit ([README](https://raw.githubusercontent.com/abiosoft/colima/main/README.md)); v0.7.0 (2024‑07‑30) added `incus`/`none` and "Each runtime now has dedicated disk images" ([v0.7.0](https://api.github.com/repos/abiosoft/colima/releases/tags/v0.7.0)). "Colima v0.6.0+ uses Ubuntu as the underlying image. No other distros are supported." ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)). Latest v0.10.3 (2026‑06‑04) ([atom](https://github.com/abiosoft/colima/releases.atom)).

**Default experience.** `colima start` = Docker with "2 CPUs, 2GiB memory and 100GiB storage" ([README](https://raw.githubusercontent.com/abiosoft/colima/main/README.md)). Config template defaults: `runtime: docker`, `rootDisk` 20GiB, `autoActivate: true` (sets Docker/K8s/Incus contexts), `portForwarder: ssh` (grpc/none options), `mountType` virtiofs (vz) or sshfs (qemu), `sshConfig: true` (edits `~/.ssh/config`), hostname `colima`, kubernetes disabled (v1.35.0+k3s1, traefik off), home mounted writable, `provision: []` ([colima.yaml](https://raw.githubusercontent.com/abiosoft/colima/main/embedded/defaults/colima.yaml)). "VZ is now the default virtual machine type on macOS 13 or newer" (v0.8.1; date unverified, API rate-limited) and virtiofs default for VZ since v0.8.3 ([releases](https://github.com/abiosoft/colima/releases)). Socket `$HOME/.colima/default/docker.sock`, contexts since v0.3.0; `DOCKER_HOST` fallback ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)). Port forwarding "Automatic"; UDP since v0.8.2 ([README](https://raw.githubusercontent.com/abiosoft/colima/main/README.md), [releases](https://github.com/abiosoft/colima/releases)).

**Extension unit and interface.** No plugin system. Extension = `provision:` entries in `colima.yaml`, "executed on startup and therefore needs to be idempotent", modes `system` (root), `user`, `after-boot` ("after VM boot, before container runtimes start"), `ready` ("after VM and container runtimes are ready") ([colima.yaml](https://raw.githubusercontent.com/abiosoft/colima/main/embedded/defaults/colima.yaml)); a `docker:` map that becomes daemon.json; per-profile containerd/buildkit TOML; escape hatch to raw Lima via `$HOME/.colima/_lima/_config/override.yaml`; profiles (`colima start debug`) ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)). `--disk-image` is for "power users and not officially supported" ([releases](https://github.com/abiosoft/colima/releases)). It ships Agent Skills markdown under `skills/` for AI assistants ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)).

**Discovery and distribution.** brew / nix / binary ([INSTALL](https://raw.githubusercontent.com/abiosoft/colima/main/docs/INSTALL.md)); runtime images downloaded from GitHub (`diskImage` overrides "GitHub downloads") ([colima.yaml](https://raw.githubusercontent.com/abiosoft/colima/main/embedded/defaults/colima.yaml)). No catalog: Lima templates are not used; Colima generates its own Lima config. `colima template` edits the default for new profiles ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)); implicit template loading was disabled in v0.8.4 and reinstated in v0.9.0 ([releases](https://github.com/abiosoft/colima/releases)).

**Overriding defaults.** Flags (`--cpu --memory --disk`), `colima start --edit`, `~/.colima/default/colima.yaml` (XDG fallbacks) ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)); "Virtual machine type, architecture, runtime and volume mount type cannot be changed after the virtual machine is created" (v0.7.0 added a warning) ([v0.7.0](https://api.github.com/repos/abiosoft/colima/releases/tags/v0.7.0)).

**Lessons.** Breaking upgrades: v0.6.0 (2023‑11‑12): "Due to breaking changes, deletion of existing profiles is required via `colima delete`… Existing containers, images and volumes would be lost after upgrade" ([v0.6.0](https://api.github.com/repos/abiosoft/colima/releases/tags/v0.6.0)); the FAQ's generic upgrade path is still `colima delete && colima start`, mitigated by `colima update` (v0.7.6+) and a persistent data disk (v0.9.0, "no guarantees against loss of data") ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md), [releases](https://github.com/abiosoft/colima/releases)). Mounts: issue #544 (2022‑12‑27, DDEV's rfay): "the QEMU/9p setup wasn't even worth waiting for; it's as bad as Docker Desktop alone used to be" ([#544](https://github.com/abiosoft/colima/issues/544)); today's default is sshfs on QEMU, virtiofs on VZ. Leaky base: "Mount paths containing spaces … are not supported by the underlying Lima runtime" ([FAQ](https://raw.githubusercontent.com/abiosoft/colima/main/docs/FAQ.md)). "Why not bare Lima?" is asked outright in #1349 (2025‑07‑28); answer: "a more tailored experience" for containers ([#1349](https://github.com/abiosoft/colima/discussions/1349)). Users value it as a reliable one-command Docker Desktop replacement: "The amount of times I needed to curse at Colima was zero" ([HN](https://news.ycombinator.com/item?id=36669121)).

## 3. Multipass

**Core.** "A lightweight VM manager for Linux, Windows and macOS… spin up a fresh Ubuntu environment with a single command"; KVM on Linux, Hyper-V on Windows, QEMU on macOS, VirtualBox alternative ([README](https://raw.githubusercontent.com/canonical/multipass/main/README.md)). 1.16.0 (2025‑07‑10): "Fully open source. Previously proprietary bits for Windows and macOS are now part of this repository"; "LXD and libvirt drivers are being deprecated, along with blueprints. The plan is to remove them in the next feature release" ([1.16.0](https://api.github.com/repos/canonical/multipass/releases/tags/v1.16.0)). Latest 1.16.4 (2026‑09‑08); no 1.17 yet ([releases API](https://api.github.com/repos/canonical/multipass/releases?per_page=20)). Root daemon `multipassd` ([#579](https://github.com/lima-vm/lima/discussions/579)).

**Default experience.** `multipass launch` with nothing: "the latest Ubuntu LTS will be used"; 1 CPU (min 1), 1G RAM (min 512M), 5G disk (min 1G); random name ("relishing-lionfish"); the name `primary` auto-mounts home; `--cloud-init` takes "Path or URL to a user-data cloud-init configuration, or '-' for stdin" ([launch](https://canonical.com/multipass/docs//en/latest/reference/command-line-interface/launch/)).

**Extension unit and interface.** Blueprint YAML: required `description`, `version`, `instances.<name>` ("equal to the blueprint name"); optional `runs-on`, `image`, `limits` (`min-cpu`, `min-mem`, `min-disk`), `timeout`, `cloud-init.vendor-data`, `health-check` ([blueprints README](https://raw.githubusercontent.com/canonical/multipass-blueprints/main/README.md), [doc](https://canonical.com/multipass/docs/stable/explanation/blueprint/)). Example `docker.yaml` v0.4: runs-on arm/arm64/power64/s390x/x86_64, Ubuntu 24.04, `workspace: true`, min 2 CPU/4GB/40GB, cloud-init installs Docker+Portainer, health-check `docker run hello-world` ([docker.yaml](https://raw.githubusercontent.com/canonical/multipass-blueprints/main/v1/docker.yaml)). So the lifecycle is image → cloud-init (install/configure) → health-check (check); no sign-in hook. Aliases: `multipass alias instance:command [name]` creates scripts on PATH, maps cwd into mounted dirs (`--no-map-working-directory`), plus `aliases`/`unalias`/`prefer` ([alias](https://canonical.com/multipass/docs//en/latest/reference/command-line-interface/alias/)); shipped in 1.8.0 (2021‑10‑26) ([1.8.0](https://api.github.com/repos/canonical/multipass/releases/tags/v1.8.0)).

**Discovery and distribution.** Curated GitHub repo `canonical/multipass-blueprints`, files `v1/<name>.yaml`, fetched by the daemon from `MULTIPASS_BLUEPRINTS_URL` (override via `systemctl edit` on Linux) ([README](https://raw.githubusercontent.com/canonical/multipass-blueprints/main/README.md)); `multipass find --only-blueprints`, `multipass launch docker --name docker-dev --cpus 4 --memory 8G --disk 50G --bridged` ([how-to](https://canonical.com/multipass/docs/stable/how-to-guides/manage-instances/use-a-blueprint/)). History: 1.8.0 shipped "[workflows] `runs-on` support" pointing at `multipass-workflows` ([1.8.0](https://api.github.com/repos/canonical/multipass/releases/tags/v1.8.0)); 1.9.0 (2022‑05‑03): "Renaming of Multipass Workflows to Multipass Blueprints" ([1.9.0](https://api.github.com/repos/canonical/multipass/releases/tags/v1.9.0)); deprecated 1.16.0. Docs now say: "Blueprints are deprecated and will be removed in a future release. You can achieve similar effects with cloud-init and other launch options." ([doc](https://canonical.com/multipass/docs/stable/explanation/blueprint/)). The replacement is literally a cloud-init file by URL: Canonical's own charm tutorial swapped `multipass launch … charm-dev` for `multipass launch 24.04 … --cloud-init https://raw.githubusercontent.com/canonical/multipass/refs/heads/main/data/cloud-init-yaml/cloud-init-charm-dev.yaml` ([mysql-operators PR #508](https://github.com/canonical/mysql-operators/pull/508)).

**Overriding defaults.** Per-launch flags (`--cpus/--memory/--disk/--mount/--network/--bridged/--timeout`) ([launch](https://canonical.com/multipass/docs//en/latest/reference/command-line-interface/launch/)); blueprint `limits` are minimums the CLI can raise ([doc](https://canonical.com/multipass/docs/stable/explanation/blueprint/)). No layered config-file override system comparable to Lima's `_config`.

**Lessons.** Networking is the perennial complaint: "Unfortunately the default switch is known to be quirky and Windows updates often put it in a weird state"; on macOS the firewall must not block incoming, and "VPN software can be aggressive at managing routes and may route 192.168.64 subnet through the VPN interface" ([troubleshoot](https://canonical.com/multipass/docs/latest/how-to-guides/troubleshoot/troubleshoot-networking/)). Lima's maintainer: "multipass doesn't support localhost port forwarding that is present in Lima (and WSL2)", Ubuntu-only, needs root ([#579](https://github.com/lima-vm/lima/discussions/579)). 1.15.0 dropped macOS <13 ([releases API](https://api.github.com/repos/canonical/multipass/releases?per_page=20)). The blueprint arc (2021 → renamed 2022 → deprecated 2025 → removal pending) shows a curated catalog with pinned images, per-arch lists and a health-check is a maintenance liability; Canonical collapsed it to plain cloud-init files hosted in the main repo and passed by URL.

## 4. Vagrant

**Core.** Ruby `Vagrantfile` + boxes + providers + provisioners + plugin API; "most of the core of Vagrant is implemented using plugins" and Vagrant "dogfoods its own plugin API" ([plugins](https://developer.hashicorp.com/vagrant/docs/plugins)). Latest 2.4.9 (2025‑08‑21) ([CHANGELOG](https://raw.githubusercontent.com/hashicorp/vagrant/main/CHANGELOG.md), [releases](https://releases.hashicorp.com/vagrant/)). License: "Business Source License 1.1", Licensor IBM, "Vagrant 2.4.3 or later", Change License MPL 2.0 after four years ([LICENSE](https://raw.githubusercontent.com/hashicorp/vagrant/main/LICENSE)).

**Default experience.** There is no zero-config run: `config.vm.box` has no default ("This configures what box the machine will be brought up against") ([machine_settings](https://developer.hashicorp.com/vagrant/docs/vagrantfile/machine_settings)); the tutorial path is `vagrant init hashicorp/bionic64` ([boxes](https://developer.hashicorp.com/vagrant/docs/boxes)). Provider choice: `--provider` > `VAGRANT_DEFAULT_PROVIDER` > `config.vm.provider` order > "the first plugin that reports it is usable" (VMware ranked above VirtualBox) > error ([providers](https://developer.hashicorp.com/vagrant/docs/providers/basic_usage)). Provisioning runs on first `vagrant up`, `vagrant provision`, `vagrant reload --provision`; `--no-provision` skips ([provisioning](https://developer.hashicorp.com/vagrant/docs/provisioning)).

**Extension unit and interface.** A plugin is a RubyGem whose class inherits `Vagrant.plugin("2")`; it "must _always_ load, no matter what version of Vagrant is running" (lazy-loaded components) ([dev basics](https://developer.hashicorp.com/vagrant/docs/plugins/development-basics)). Extension points: commands, configuration, guests, guest capabilities, hosts, host capabilities, providers, provisioners, synced folders, action hooks ([plugins](https://developer.hashicorp.com/vagrant/docs/plugins), [dev basics](https://developer.hashicorp.com/vagrant/docs/plugins/development-basics)). Built-in provisioners: shell, file, ansible, ansible_local, cfengine, chef solo/zero/client/apply, docker, podman, puppet apply/agent, salt ([provisioning](https://developer.hashicorp.com/vagrant/docs/provisioning)); `run: "once"|"always"|"never"`, `before`/`after` with `:each`/`:all`, "ordering is _outside in_" ([basic_usage](https://developer.hashicorp.com/vagrant/docs/provisioning/basic_usage)). No built-in check/health hook. "Boxes are the package format for Vagrant environments", versioned ([boxes](https://developer.hashicorp.com/vagrant/docs/boxes)).

**Discovery and distribution.** `vagrant plugin install NAME` from RubyGems or a local `.gem`; `--plugin-source`, `--plugin-version`, `--local`; `list/update/uninstall/expunge/repair/license` ([usage](https://developer.hashicorp.com/vagrant/docs/plugins/usage), [cli](https://developer.hashicorp.com/vagrant/docs/cli/plugin)). Boxes via HCP Vagrant Registry, "a public, searchable index of Vagrant boxes"; Vagrant Cloud accounts moved to HCP in December 2022 ([hcp](https://developer.hashicorp.com/hcp/docs/vagrant)); 2.4.3 (2024‑11‑12) "Support HCP authentication" ([CHANGELOG](https://raw.githubusercontent.com/hashicorp/vagrant/main/CHANGELOG.md)). Now: "End of new Box/Registry creation: October 1, 2026. End of support and maintenance: November 2, 2026. End of operations: December 31, 2026", with export, S3 guidance and a static archive promised ([EOL](https://developer.hashicorp.com/hcp/docs/vagrant/hcp-vagrant-eol)).

**Overriding defaults.** Load order: (1) "Vagrantfile packaged with the box", (2) "Vagrantfile in your Vagrant home directory (defaults to `~/.vagrant.d`)", (3) "Vagrantfile from the project directory", (4) multi-machine overrides, (5) provider-specific overrides; later levels override, some settings (networks) append; lookup climbs parent dirs, `VAGRANT_CWD` overrides ([vagrantfile](https://developer.hashicorp.com/vagrant/docs/vagrantfile)). Note: the docs list no system-wide tier; the "system, user, project" triple in the question is not how Vagrant documents it.

**Lessons.** BUSL announced 2023‑08‑10 ([blog](https://www.hashicorp.com/blog/hashicorp-adopts-business-source-license)). Distro fallout: openSUSE (2023‑11‑03): "due to Hashicorp changing the license of vagrant to the BUSL, we can no longer update vagrant in openSUSE" ([mail](https://www.mail-archive.com/ruby@lists.opensuse.org/msg00007.html)); Ubuntu bug 2054608 (2024‑02‑21): "the Debian maintainer … said that it is in his TODO list to remove vagrant and related packages from Debian"; Ubuntu removed it from Noble on 2024‑02‑28 ([launchpad](https://bugs.launchpad.net/bugs/2054608)). No community fork surfaced in searches (negative result, unverified). Vagrant 3: plan announced 2021‑06‑11 (2.3 optional Go, 2.4 Go primary, 3.0 Go-only) ([blog](https://www.hashicorp.com/blog/toward-vagrant-3-0)); 2.3.0 (2022‑08‑05) "core: Introduce vagrant-go"; 2.4.4 (2025‑04‑21) "VAGRANT-GO: Removed with work archived to vagrant-go branch" ([CHANGELOG](https://raw.githubusercontent.com/hashicorp/vagrant/main/CHANGELOG.md)); PR #13622 (merged 2025‑03‑17): "Removes the vagrant-go implementation. A backup of the work has been retained on the `vagrant-go` branch" ([PR](https://github.com/hashicorp/vagrant/pull/13622)); community verdict "Vagrant in Go is officially dead" ([discuss](https://discuss.hashicorp.com/t/is-vagrant-3-0-still-happening/40786)). Maintenance doubt: "there hasn't been any development activity since the end of 2021" (issue #12752, 2022‑04‑26) ([issue](https://github.com/hashicorp/vagrant/issues/12752)). Plugin breakage is institutionalised: "3rd party plugins can introduce instabilities" ([usage](https://developer.hashicorp.com/vagrant/docs/plugins/usage)); `repair`/`expunge --reinstall` exist because "Vagrant may fail to properly initialize user installed custom plugins" ([cli](https://developer.hashicorp.com/vagrant/docs/cli/plugin)); e.g. after 1.9.0: "If Vagrant was recently updated, this error may be due to incompatible versions of dependencies. To fix this problem please remove and re-install all plugins" ([#8054](https://github.com/hashicorp/vagrant/issues/8054)). VirtualBox coupling: Apple Silicon support was asked in 2020 ([#12051](https://github.com/hashicorp/vagrant/issues/12051)); VirtualBox only gained "macOS/Arm host: Arm virtualization for Linux and BSD VMs" in 7.1.0 (2024‑09‑09) ([vbox](https://www.virtualbox.org/wiki/Changelog-7.1)), tracked by Vagrant 2.4.2/2.4.9 ([CHANGELOG](https://raw.githubusercontent.com/hashicorp/vagrant/main/CHANGELOG.md)).

## Cross-cutting takeaways for a core / default / packs split

- Survivors have an explicit bare switch and an opinionated default: Lima `--plain` vs `default.yaml`; Colima's fixed Docker profile. Vagrant never had a default box, so first run is homework.
- Curated catalogs decay: Multipass blueprints (4 years, then "use cloud-init"), Lima's Lost+found, HCP registry EOL. A pack should be a fetchable file (URL/git) with version pin and a health check, not an in-tree catalog you must keep green.
- PATH executables (`limactl-<name>`, `limactl-url-<scheme>`) decouple plugins from the core's release cycle; interpreter-bound gems broke on every Vagrant upgrade.
- "Check" hooks exist in three of four (Lima readiness probes, Multipass health-check, Colima `ready` mode); none has an install/configure/sign-in lifecycle — that is open space.
- Breaking changes belong in majors with CLI hints (Lima v1/v2); Colima's `colima delete` upgrades and Lima's read-only home show that surprising defaults are tolerated only with a one-flag escape hatch.
